# NovelForge 真机测试项目（v0.1.6 基线）

> **这份文档是什么**：一份**在真实安装产物上执行**的测试项目（test project）——含测试环境准备、专用测试夹具（fixture）、约 50 条编号用例、通过标准与结果记录表。
> **谁执行**：发版人（或指定的真机测试者）；本档按「照着做就能跑完」编写，不假设执行者读过源码。
> **何时执行**：见 §1.3 触发时机。
> **基线**：v0.1.6（正式版，Schema v17，单测 107 files / 1254 tests）——用例编号和预期结果按此基线写定；换基线需复核预期列。

## 1. 范围与定位

### 1.1 单测覆盖不到的是什么

`pnpm run test` 跑的是 vitest + mock：`better-sqlite3`、LanceDB、jieba-wasm 的 `.wasm`、Electron 外壳、真实 LLM/embedding 全都不在其中。以下只能真机验：

| 类别 | 单测为什么覆盖不到 |
|---|---|
| **打包产物内的原生/二进制依赖** | `jieba-wasm` 的 `.wasm` 在 asar/白名单配错时**主进程启动即崩**；测试里是 mock 或源码路径，永远绿 |
| **跨重启续跑** | L2 把 checkpoint 从 localStorage 迁到 DB，只有真的「关掉应用再打开」才算验过 |
| **数据目录迁移** | `.vela/` → `.novelforge/` 的迁移只在真实用户目录（`~/.vela` 已存在）下才走真实分支 |
| **真实 LLM / embedding 链路** | 别名扩展对 top-K 与阈值命中率的影响、意图预路由的实际分类质量、压缩恢复阶梯的实际触发 |
| **三语界面** | 单测只断言 key 存在；排版溢出、俄语长串截断、主进程弹窗语言只有肉眼能看出来 |
| **更新器** | `latest.yml` + `.blockmap` 与安装包的匹配只有真机升级才验得出 |
| **人工观感** | 内联接受浮条的 n:m 提示、Ctrl+Y 重做手感、浮窗定位 |

### 1.2 与发版流程的关系

`.agents/skills/novelforge-release/SKILL.md` 的 **R5「dev 冒烟清单」是开发机上的轻量版**（`2026-08-28-release-prep.md` Task R5，12 条）。
**本档是「打包产物 + 真机」版本，两者都要跑**：R5 在提交前抓开发期回归，本档在构建后抓打包/环境回归。

| 版本类型 | 本档执行范围 |
|---|---|
| 内测 alpha | A 组（安装启动）+ 本次改动相关的组 |
| 公测 beta | A + B + C + D 组（必跑）+ 本次改动相关组 |
| 正式版 | **全量**（A–L） |

### 1.3 触发时机

1. 每次**构建出产物之后**（alpha/beta/正式版都适用）；
2. 引入/修改**原生依赖、打包白名单、数据目录、迁移**的改动后（必跑 A 组）；
3. 引入/修改**检索链路、embedding**的改动后（必跑 B 组）；
4. 发版前的最后一道人工关。

## 2. 环境与产物准备

### 2.1 产物

| 产物 | 路径 | 用途 |
|---|---|---|
| 安装版 | `release/{type}/{v}/NovelForge-{v}-Installer/NovelForge-{v}-Installer.exe` | A 组主用（装到真实用户目录，验升级/卸载） |
| 便携版 | `release/{type}/{v}/NovelForge-{v}-Portable.7z` | 免安装快速复跑（`{type}` = `alpha`/`beta`/`stable`） |

⚠️ **alpha 版不产 7z**（构建脚本跳过压缩），只用安装版或 Portable 目录。

### 2.2 三套用户环境（用于 J 组迁移与 A 组启动，互不污染）

| 环境 | 准备方式 | 验什么 |
|---|---|---|
| **① 干净环境** | 确保 `~/.novelforge`（Windows：`C:\Users\<你>\.novelforge`）**不存在** | 首次启动、默认配置生成、无 `~/.vela` 时的路径选择 |
| **② 旧版升级环境** | 先装 **v0.1.5**（或更早），用一次产生 `~/.vela` + 一个项目（项目内 `.vela/`），再装本版 | `~/.vela` → `~/.novelforge` 迁移、项目 `.vela/` → `.novelforge/` 惰性迁移、双路径兜底 |
| **③ 已有项目环境** | 常规使用中的环境（已有多个项目 + 最近项目列表） | 回归：老项目打开、角色卡、检索、记忆不被破坏 |

> 验迁移**必须**有环境②。没有旧版产物时，可手工造：在 `~/.vela/` 放一份 v0.1.5 的 `config.json` 与一个项目目录（内含 `.vela/vela.db`）。

### 2.3 配置准备

| 项 | 要求 | 关联用例 |
|---|---|---|
| LLM | **至少一个真实 provider 的有效 Key**（不是占位） | E、G、H、L 组 |
| Embedding | **真实 embedding provider**（本地 Ollama 或云端均可） | B 组别名扩展用例（**无 Key 无法验，这是 L3 的发布前置项**） |
| 语言 | zh-CN / en-US / ru-RU 三语各切一遍 | I 组 |
| 日志 | 记录路径 `~/.novelforge/logs/vela-YYYY-MM-DD.log`（文件名随日期） | 多组用日志做证据 |

### 2.4 记录方式

每条用例填「结果」列：`通过` / `失败` / `阻塞（原因）`；失败与阻塞项**必须**附证据——日志片段、截图、或复现步骤。用 §6 的表格汇总。

## 3. 测试夹具（RM-FIX-1：专用测试项目）

> 目的：让检索/记忆/角色用例**有确定的输入与确定的预期**，避免用真实创作项目导致判定主观。
> 命名建议：项目名 `RM-FIX-1-真机测试-{YYYYMMDD}`。

### 3.1 项目与角色

新建小说项目 `RM-FIX-1-真机测试`，建以下角色卡：

| 角色 | 正名 | 别名（aliases） |
|---|---|---|
| 主角 | `苏晚` | `阿晚`、`晚儿` |
| 配角 | `林动` | `林兄` |

> 别名是 L3 查询改写的输入（characters v14 `aliases` 列，JSON 数组）。

### 3.2 知识库素材（导入 3 份 `.txt`）

**文件 1 `RM1-设定.txt`**（跨章通用设定，无章节号——验「NULL 章节号也纳入范围检索」）：

```
云海之上有一座浮空剑宗，宗主苏晚持一柄名为「霜月」的古剑。
剑宗规矩：弟子不得私自下山。林动是苏晚的师弟，负责看守藏剑阁。
```

**文件 2 `RM2-第一章素材.txt`**（含正名与别名混用——验别名扩展召回）：

```
阿晚在月光下擦拭霜月剑，剑身映出晚儿自己的脸。
她想起林兄说过的话：藏剑阁的第三层从不对外开放。
```

**文件 3 `RM3-无关干扰.txt`**（高频虚词密集——验词级 AND 不被噪声撑满）：

```
的了是在有的和与这那我你他她它的了是在有的和与这那我你他她它
的月光的确很亮，但是的了噪声不应该撑满候选池，的了是在有的和与。
```

> 素材 3 是**负样本**：改造前逐字 LIKE 会大量命中它（「的」「月」逐字），词级 AND + 噪声词过滤后它不应挤掉素材 2。

### 3.3 章节与正文

至少建 3 章并写入可辨识词，供 B/C/D/E 组使用：

| 章 | 关键句（用于检索断言） |
|---|---|
| 第 1 章 | `主角的剑在月光下` |
| 第 2 章 | `搜索知识库` |
| 第 3 章 | `霜月剑有三道封印` |

### 3.4 夹具校验（跑 B 组前确认）

- [ ] 知识库导入成功，3 份文档都出现在列表里，chunk 数 > 0
- [ ] `~/.novelforge/logs/` 当天日志里**没有** `ChineseTokenizer jieba-wasm 加载失败，分词降级`
- [ ] 触发一次「分词回填」（知识库页面的回填入口）且无失败计数异常（新建项目此步应为 0 条待回填，属正常）

## 4. 用例矩阵

> 状态列空白待填：`通过` / `失败` / `阻塞`。

### A 组 — 安装、启动、打包产物（**每次构建必跑**）

| A2 | **jieba-wasm `.wasm` 加载**（L3 发布前置项） | 打开项目 → 建知识库 → 检索一次中文 query → 查当天日志 | 日志**无** `jieba-wasm 加载失败，分词降级`；中文检索能按词命中（不是整句一个 token 的退化行为） | |

### B 组 — 知识库检索（L3 中文检索升级，**beta/正式必跑**）

| # | 用例 | 步骤 | 预期 | 结果 |
|---|---|---|---|---|
| B1 | 词级命中 | 检索 `主角的剑` | 命中第 1 章关键句；结果 `source` 为 `fts` 或 `vector` | |
| B2 | **噪声不撑满候选池** | 检索 `月光`，观察是否被素材 3 挤满 | 素材 1/2 的相关块在结果里；素材 3 不占满全部名额 | |

| B5 | tokens 缺失回退 | 对老项目（v0.1.5 建的知识库，未回填）直接检索 | 仍能命中（退回逐字 LIKE 兜底，行为不劣于改造前） | |

| B7 | 别名扩展失败降级 | 断开 embedding（清 Key）后检索 `阿晚` | 不报错、不阻塞；退回原样 query 的检索行为 | |
| B8 | 回填幂等 | 连续执行两次分词回填 | 第二次 processed 为 0（不重复处理） | |
| B9 | 跨项目隔离 | 建第二个项目并配同名角色 → 在项目 1 检索 | 不并入项目 2 的别名（无跨项目污染） | |
