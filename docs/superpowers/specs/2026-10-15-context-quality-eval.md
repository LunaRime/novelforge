# 上下文质量用例集（§4 度量口径）

> **状态**：**已建立（2026-10-15，随批 3 落地）**。A 部分（确定性）已在 CI 内运行；B 部分（真机行为指标）待跑。
> **依据**：`docs/superpowers/plans/2026-10-15-context-quality-by-model-tier-plan.md` §4
> **双轨口径**：S = 强模型能力上限不被上下文层拖累；W = 弱模型下限被抬高

## 0. 为什么要有它

上下文工程的改动天然"说不清好坏"——很容易退化成"凭感觉调提示词"。本档给两把尺子：

| 部分 | 测什么 | 能否自动跑 | 覆盖的变化 |
|---|---|---|---|
| **A 确定性（CI）** | **上下文层**的结构不变量：任务状态是否存活、被截断的工具是否仍可调用、召回是否越界、预算是否守住 | ✅ 每次 CI | S1/S2/W2/W1/W3/W4 的**机制** |
| **B 真机（需真实模型）** | **模型行为**指标：跨轮事实保持率、任务完成轮数、过早收尾率、摘要保真率 | ❌ 手动/真机 | 这些机制**是否真的让模型变好** |

> ⚠️ **诚实边界**：A 部分只能证明"机制就位且未被后续改动破坏"，**不能**证明"生成质量提升"。
> 任何"锚点/召回提升了质量"的说法都必须由 B 部分背书，否则只是结构证据。

## A. 确定性部分（CI 内运行）

**位置**：`src/services/agent/context-quality.test.ts`（`pnpm run test` 自动执行）
**运行**：`pnpm vitest run src/services/agent/context-quality.test.ts`

| # | 场景 | 断言 | 它排除的失败模式 |
|---|---|---|---|
| A1 | **任务锚点活过压缩** | 会话已有 2 个压缩批次 + 长历史时，system 仍含本轮诉求要点，且位于语言指令之前 | 任务状态被压进摘要后消失（S2/W2 的核心承诺）；语言指令被挤离末尾（#30 语义） |
| A2 | **降级链末端的工具仍可调用** | 工具集撑到超预算 → 提示词被截断 → **截断通知的签名清单仍含每一个已注册工具** | "看不见的工具 = 不可调用"（P0-3 教训）；工具增长时静默失去可调用性 |
| A3 | **弱档召回精度与预算** | 弱档 + 命中消息 → 出现召回段且 ≤400 tokens；未命中 → 无段；**强/标准档即使命中也不注入** | 召回退化成"每轮塞记忆"；强模型被自动注入挤占预算 |
| A4 | **三档预算不变量** | 强/标准/弱三档下 system 总量 ≤ 各自上限；语言指令恒最末 | 档位策略把预算算爆；降级链顺序被改坏 |
| A5 | **M1 注入不越界** | 超长滚动摘要 + 弱档（200）→ M1 段 ≤ 200 + 标题开销 | 摘要长度与注入上限脱钩（"死额度"的反面：注入端越界） |

## B. 真机部分（需真实模型，手动执行）

**前置**：一次性夹具项目（小说配置 + 蓝图 ≥ 3 章 + 2 个角色卡 + 1 条 manual 记忆 + 1 个分卷），
建议命名 `RM-CTX-<日期>`；全部在夹具项目上做，勿用真实创作项目。

| # | 场景 | 操作 | 指标 | 通过线 |
|---|---|---|---|---|
| B1 | **跨轮事实保持** | 第 3 轮确认一条设定（如"主角佩剑名为霜落"）→ 继续对话到第 12 轮（**确保历史被压过 ≥2 批**，可用小窗口模型或调小 `historyMaxTokens`）→ 问"主角的佩剑叫什么" | 答对 / 答错 | 弱档不得低于基线；强档不得下降 |
| B2 | **长任务不跑偏** | 提一个明确的多步请求（"先写第 1 章，然后检查伏笔，最后更新角色卡"）→ 数模型实际完成的步骤数 | 完成步骤数 / 是否在两步后停 | 弱档完成步骤数 ≥ 基线 + 1（W4 的目标） |
| B3 | **过早收尾率** | 同一多步请求跑 5 次，统计"未完成就宣告完成"的次数 | 过早收尾次数 / 5 | 弱档低于基线 |
| B4 | **摘要保真率** | 压缩发生后，对照被压缩批次原文与摘要，人工/半自动统计关键实体（角色名、章节号、写入目标）保留比例；`evaluation_scores` 可留档 | 保留率 | 不低于基线；`ccr-fidelity` 的自动值应与之同向 |

**基线怎么来**：把 A/B 两部分在**改动前**的版本上各跑一遍（A 用 git stash 或上一个 tag；B 用当前发布版），
记录数字后再改动。**没有基线的对照不构成结论。**

**执行资产**：真机档的评审可用既有互评链（`mutual-evaluation-workflow`：spawn-reviewers → synthesize-scores，
落 `evaluation_scores` 表），也可先人工跑 5 例建立基线。

## C. 与各批次的对应

| 批次 | 覆盖的机制 | 由哪些场景守 |
|---|---|---|
| 批 1（S1 降级可见 / S2+W2 任务锚点 / C1） | 降级状态可见、锚点免压缩、阈值逐字 | A1、A4（+ 批 1 的单元与 store 用例） |
| 批 2（W1 档位策略 / S3 上限） | 三档预算与上限、长窗口全量契约 | A2、A4 |
| 批 3（W3 召回 / W4 自检） | 召回精度与预算、多步自检一次性 | A3（+ W4 的引擎用例） |
