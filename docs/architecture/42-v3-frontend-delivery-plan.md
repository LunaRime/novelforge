# NovelForge V3 前端重构与落地计划

> 2026-11-19。合并原第 25 号前端重构计划与 V3 样板方案，以本文件跟踪 U0–U7。界面样式以 V3 原型为主，工程拆分、业务契约和发布验收沿用第 25 号计划的要求。完成对应证据后再勾选。

**目标**。把 V3 的写作态、构建态、稿纸和写作搭档接到现有 NovelForge 工作台，交付可持续编辑、保存和重开的桌面体验。

**架构**。保留一个 React 工作台和一个文档会话。布局层负责区域显示与切换，组件负责呈现，正式业务沿用 renderer adapter、应用用例和类型化 IPC。样板使用合成数据，产品入口使用真实项目数据。

**基线**。以 `812edd6` 的已合并工作台和 `abb0aa8` 的 Windows 候选激活包为核对起点。V3 原型中 `.program-window` 定义界面布局、稿纸、工具区与状态的视觉方向，`tokens.css` 提供设计参考，正式样式映射到应用现有主题令牌。外层评审页和脚本演示用于解释设计。[V3 原型](../ui-redesign-v3/index.html)、[原型交互](../ui-redesign-v3/v3-views.js)、[U0 样板与基线](43-v3-u0-baseline.md)

## 1. 要落地的设计

| V3 方向 | 正式界面行为 | 实现落点 | 完成标准 |
| --- | --- | --- | --- |
| 两种工作状态 | 构建态保留项目结构和任务入口。写作态默认收起项目上下文和底部运行区，保留正文、可召回的写作搭档和模式切换 | `App.tsx`、`layout-store.ts`、左右工具栏 | 同一篇正文切换两种状态时，标签、输入、光标、撤销记录、滚动和运行中的任务保持连续 |
| 四层工作台 | 工具栏切功能，侧栏给当前项目上下文，中心承载文档，右侧和底部展示 Agent、输出与运行状态 | `components/layout/`、`Sidebar.tsx`、`EditorArea.tsx`、`BottomPanel.tsx` | 项目树、知识库、Agent、任务和设置都有可达入口，隐藏的面板可通过命令或可见控制重新打开 |
| 稿纸与阅读 | 稿纸宽度、正文排版和界面密度各自调节。写作态提供较宽的正文区域，已有字号、字体、行距、打字机和段落聚焦设置优先 | `CodeMirrorEditor.tsx`、`novel-editor.css`、`editor-prefs-store.ts`、`ThemeSection.tsx` | 四主题下正文、选区、光标和只读状态清楚，切换外观后编辑会话保持原状态 |
| 写作搭档 | 同一个 Agent 会话在两种状态下采用适合的呈现。显示本次引用、等待用户处理的建议和实际应用结果 | `AIPanel.tsx`、`AgentConversation.tsx`、`AgentInputBox.tsx`、`AIOutputPanel.tsx` | 一条建议可以预览、采纳或保留原文。采纳前确认对应项目、文档、会话及正文版本，提交回执对应具体建议 |
| 样式与控件 | 将 V3 的表面、强调色、间距和排版映射到现有语义令牌。操作、折叠、焦点和弹窗复用产品组件 | `src/index.css`、`theme-store.ts`、`MenuRow.tsx`、`HoverSwapIcon.tsx`、`Dialog.tsx` | 界面密度只改留白。图标目标桌面至少 32×32 px，触屏至少 44×44 px。状态具有文字或可访问名称 |

### 本轮产品取舍

- 第一批样板采用「写作态与构建态」「正文稿纸」「写作搭档」三项，项目导航、任务和设置继续沿用正式应用入口，随后逐项调整。
- 原型的比较表、演示数据、主题展示和设计令牌说明保留为评审材料。应用内容来自真实操作、项目事实与运行状态。今日目标只在现有项目有有效目标数据时显示。
- 两种工作状态与现有专注模式分工清楚。工作状态控制区域组合，专注模式沿用既有快捷键和正文聚焦行为。`Ctrl+M` 是原型按键，U0 核对平台及用户已有绑定后再登记正式快捷键。
- 颜色、密度和外观优先复用现有持久化设置。定制壁纸、全量自绘控件与动画属于样本的扩展方向，待首个真实版本验收后再决定是否纳入。
- 面板尺寸由布局库管理，现有 layout store 管理开关和视图。默认比例用百分比字符串，最小尺寸用像素。面板在松手后执行关闭判定，旧偏好需可读并可恢复默认。
- 公共控件使用现有字号、图标、行高和圆角刻度，并按七级语义层级管理浮层。模态提供可见关闭、Esc、明确的遮罩行为、焦点回收和背景锁。三语文本使用 `t()`，重点核对窄栏和俄语长文案。

| 界面状态 | 约定反馈 |
| --- | --- |
| 加载 / 空态 / 局部失败 | 加载完成后再显示空态和创建入口。刷新时保留同来源投影，失败处给出恢复动作 |
| 未保存 / 保存中 / 已保存 | 反馈对应当前文档与实际提交的快照，重复提交受控。手动保存沿用 toast 和日志，自动保存采用低干扰反馈 |
| 版本冲突 / 已保存但索引待刷新 | 冲突保留输入和双方版本。派生更新失败明确显示正文已提交，并提供刷新或诊断动作 |
| 审批 / 取消中 / 结果待核验 | 显示任务归属和可执行操作。采用实际终态，可能重复写入的操作先核验上一次提交 |

### U7 · 集成、性能与真机发布验收

- [ ] 对四主题和三语做基本覆盖，重点复测 `1024×640` 最小窗口及 `1280×800`、`1440×900`、`1920×1080`，Windows 用 100%、125%、150% 缩放核对窗口与弹窗。核对键盘路径、焦点回收、滚动和触控命中区。
- [ ] 使用 U0 同一机器和场景，至少三次测量 1,000 章导航、10 万字正文、500 条会话消息和流式输出下的正文输入。记录中位延迟、抖动、组件挂载和更新范围，按 U0 基线复核回归。
- [ ] 用 Windows 打包应用和隔离项目跑完整链路。流程包含打开、写作、保存、切模式、Agent、修稿预览合并、定稿、只读及重启。用可用的 macOS 设备核对窗口控件与快捷键，验收记录按平台填写实际结果。
- [ ] 穿插读失败、保存拒绝、版本冲突、刷新失败、切项目、同路径重开、取消/超时。核对退出或重启后的可恢复状态及派生数据。

**验收**。固定提交、包版本、截图、测试结果和主要运行证据。发布与版本号按项目原流程管理。

## 3. 每批的检查与交付

1. 先核对该批的原型参考和正式入口，用一个合成场景记录改前表现。业务行为变化补能覆盖回归的测试，视觉变化记录前后截图和计算尺寸。
2. 运行相关组件、用例和边界测试。布局和编辑的定向例子如下，后续批次替换为各自测试文件。

   ```powershell
   corepack pnpm run test src/stores/layout-store.test.ts src/components/panels/EditorArea.test.tsx src/components/editor/DraftEditor.test.tsx src/components/editor/CodeMirrorEditor.test.tsx --maxWorkers 4
   ```

3. 正式应用批次交付时运行 `typecheck`、`lint`、全量 `test`、`typecheck:core`、`test:contracts`、`check:boundaries`、`build:vite` 和 `node scripts/check-public-console.mjs`，核对依赖文件和 Git 差异。样板批次运行 `build-storybook` 和实际浏览器场景，并执行仓库通用检查。远端以实际提交的三平台 CI 为准。
4. 每批独立提交可运行的版本，并登记交付范围、接口版本、已验和待验的平台及证据。外观或布局通过回退对应代码提交恢复。偏好格式变化需验证旧值可读与默认恢复，数据契约变化需先明确前后端共同交付点。

## 4. 第一批可交付版本

U0 先固定样本与基线。U1 与 U2 的正文部分组成第一个实际版本，验收路径是 **打开作品 → 在正文输入 → 保存 → 切换写作态与构建态 → 关闭并重开**。首批另验未保存正文与运行中 Agent 的保留。该版本通过后，按 U3–U7 扩展项目导航、功能页、写作搭档细节和设置。
