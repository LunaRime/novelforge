# V3 U1 工作台施工与交互验收

**目标**。把 V3 的构建态、写作态与搭档入口接到正式工作台。作者切换布局后可以继续编辑同一处正文，并找回之前的面板和任务。

**实施条件**。首批接入普通 SQLite 项目的工作台布局，激活文件项目沿用专用编辑器入口。已有隔离项目和 Windows 基线包，用同一章做前后对照。基线验证了现有 F11、编辑会话连续性与保存重开，V3 两态、偏好及标签恢复按本批验收。[后端交接与 U1 基线](53-v3-backend-handoff.md) · [总计划](42-v3-frontend-delivery-plan.md) · [U0 基线](43-v3-u0-baseline.md)

## 画面与操作状态

| 状态 | 页面应呈现的内容 | 可达行为 |
| --- | --- | --- |
| 构建态 | 顶部显示作品及两态选择，左侧是项目导航，中间是文档，Agent 和底部区域按作者原有配置显示 | 从写作态返回后恢复原有面板开关、视图、尺寸以及当前正文标签 |
| 写作态 | 正文占据中心，项目上下文和任务区默认收起。标题、切换状态和搭档入口保持可见 | 从标题区或命令面板召回同一搭档会话与任务。第二次打开时继续使用本次会话的上下文和进度 |
| 正文有未保存输入 | 正文状态在两态中持续可读，当前行、选区和滚动位置保持 | 切换后直接继续输入，撤销和重做仍对应原操作。键盘启用切换控件后有可见焦点 |
| 窗口较窄或内容放大 | 以可用内容宽度整理工具区。正文、当前模式、保存状态、召回和缩放入口优先保留 | 逐项核对模式选择、正文保存、搭档、任务和缩放入口的中心可命中且能用 Tab 到达。展开的浮层能按 Esc 关闭并归还焦点 |
| 专注模式 | F11 继续临时收起工具区域，退出后回到原工作状态 | 构建态和写作态各跑一次 F11 往返，核对面板及正文焦点 |

画面对照从 V3 原型的 `.program-window` 与 Storybook 的 Forge、Compose 出发。先对齐标题位置、稿纸与工具区的主次、拉开与收起时的反馈。颜色、圆角、留白和字体使用应用的现有语义令牌。工具栏可见动作随宽度调整时，桌面单图标按钮的命中区至少 32×32 CSS px。[V3 原型](../ui-redesign-v3/index.html)、[样板入口](43-v3-u0-baseline.md#操作样板)

Storybook 样板用工具栏的「任务」按钮验收写作态召回，构建态和写作态各自记住开关。按钮由键盘操作并对外公布展开状态，各状态共用当前任务内容和同一个正文编辑器。已在 684×428 CSS px 验证召回后任务状态出现在工具栏下方，正文及搭档区可继续滚动查看。[样板源码](../../src/stories/V3Workbench.stories.tsx)

## 施工顺序与回归

### 1. 抽出工作台布局，保持当前桌面行为

- [x] 在 `App.tsx` 保留启动、快捷键、窗口拖拽区和全局对话框，将四区与分隔条交给 `WorkspaceLayout`。原生控件留位和缩放入口继续由现有组件提供。[布局组件](../../src/components/layout/WorkspaceLayout.tsx)
- [x] 两个布局持久化键和面板 ID 保持兼容。侧栏、Agent、底栏的拖拽下限分别为 220、260、120 CSS px，到下限松手后关闭。
- [x] 旧包与提取后的 Windows x64 打包应用使用相同的隔离夹具。两者均通过三面板拖拽、松手关闭、快捷键恢复、尺寸重启恢复及 F11 往返。CodeMirror 实例、正文与撤销历史在布局操作期间保持连续，Ctrl+S 后重启可按原草稿 ID 读回。

### 2. 接入构建态与写作态

- [x] `layout-store` 保留旧的构建态偏好键，新增写作态面板偏好和当前模式。首次进入写作态收起侧栏、Agent 和底栏。搭档、任务由工作区工具条召回，侧栏仍可用原快捷键临时打开。[状态回归](../../src/stores/layout-store.test.ts)
- [x] Windows x64 打包应用在 1440×900 CSS px 验证两态独立的面板开关和尺寸。两态都打开相同三个面板时各自恢复尺寸，重启恢复上次模式。F11 临时收起面板，退出后恢复当时模式的布局。
- [x] 实测两态往返保留同一个 CodeMirror 实例、选区、未保存输入、长稿滚动、撤销和重做。Ctrl+S 写入原草稿 ID，重启后重选原稿可读回正文。[工作台接线](../../src/components/layout/WorkspaceLayout.tsx)

### 3. 接通 V3 入口与键盘路径

- [x] 顶栏在原生窗口控件的可用区域内显示模式分段、写作态召回和命令面板按钮。模式名称覆盖三语，选中及展开状态可被辅助技术读取。
- [x] 命令面板与可自定义快捷键调用同一模式动作。模式快捷键默认未分配，保留现有 Windows 应用绑定和 macOS 窗口快捷键。设置录入时检查用户已分配的组合键。[命令面板回归](../../src/components/command-palette/CommandPalette.test.tsx) · [绑定回归](../../src/stores/shortcut-store.test.ts) · [Apple 快捷键](https://support.apple.com/en-us/102650)
- [x] 搭档和任务沿用现有面板与状态入口。Windows 打包应用从正文、导航和 Agent 输入区验证切换。正文继续聚焦，面板卸载后焦点移至可见的模式按钮。命令面板验证 Tab 限定、Escape 归还焦点与背景滚动隔离。
- [x] 状态栏窄窗优先显示保存状态和缩放，模型与思考等级仍可经搭档入口访问。Windows 俄语最小窗 1024×640 在应用缩放 125% 和 150% 下验证标题模式、召回、命令以及缩小和重置的可达性，鼠标和键盘均可恢复至 100%。

### 4. 真机交付

- [ ] Windows 打包版比对构建态、写作态、搭档召回及未保存正文四组画面。沿用长章名和运行中 Agent 的测试稿，覆盖三语、四主题和 100%/125%/150% 应用内容缩放。通过对应设备核对 Windows 系统缩放、macOS 原生控件及中文输入法。
- [ ] 对最小窗 1024×640 和 1440×900 截图，记录实际 CSS 视口、区域宽度与交互命中。已登记的正文修稿、审稿和定稿裁切由 U2 复测。U1 验收模式、搭档、任务、窗口与正文入口的可达性。
- [ ] 完成「打开作品 → 写入未保存正文 → 往返切换 → Ctrl+S / Cmd+S → 关闭 → 重开」并回读正文。将已验的平台、代码提交、包版本与截图写入验收记录。
