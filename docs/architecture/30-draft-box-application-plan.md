# C1g 草稿箱接入实施计划

2026-11-12，基线 `2d4c7aa`。承接 [18 总计划](18-followup-implementation-plan.md)、[15 编辑器应用层](15-editor-application-plan.md) 与 [16 修稿合并](16-revision-merge-application-plan.md)。按任务先复现失败，再实现和验收。

目标是让草稿箱基于当前项目会话的列表，通过已有编辑器用例打开选中的真实草稿版本，并安全归档该版本。草稿箱通过编辑器现有修稿入口进入原子合并。

## 任务 1　打开指定草稿

- [x] 为 `EditorOpenRequest` 增加 `{ kind: 'draft'; draftId: number; name: string }`，在 renderer 适配器按 ID 严格读取。沿用 `doc:{id}` 与 `vela://draft/{id}`，同章、同版本的不同分支保持独立。成功空正文可以打开，缺稿或读取失败通过侧栏反馈，切项目时取消发布。
- [x] 草稿箱行按钮和菜单共用 `openDraftById`。编辑器重开时保留 dirty 与 inline 会话的正文。现有编辑器使用 `mergeRendererRevision`，在本批验证从草稿箱打开后的 tab 和既有合并适配器可互操作。
- [x] 验证 `open-editor-document.test.ts`、`SidebarShared.test.ts`、`merge-revision.test.ts` 和 `DraftBoxGroup.test.tsx`。

## 任务 2　列表来源与标题

- [x] draft-store 发布列表时同时标记项目 id/path/session。草稿箱与项目树里的正式稿、活页夹只使用当前会话的数据。按章更新不得合并另一项目的列表。切换失败后，按已结束的会话重新读取当前项目。
- [x] 草稿箱在章节集合或蓝图刷新事件变化时经现有严格快照适配器读取标题。读取失败保留草稿列表，缺标题时显示本地化章号。先返回的旧请求不得覆盖较新的标题。组件不直接发送蓝图 IPC。
- [x] 测试缺蓝图、蓝图读取失败、同路径重开、标题刷新竞争与草稿正文读取失败。

## 任务 3　归档保护

- [x] 草稿箱保留原确认弹窗。确认前后检查同一项目来源，同一草稿只允许一个待确认或待提交操作。
- [x] 新增 `db:draft-archive`，输入为项目路径、真实草稿 ID 和章号。主进程先检查当前路径，再使用单条条件 UPDATE，按 ID 和章号归档，拒绝已定稿、已归档和不存在的行。回执返回实际写入时间，权限按破坏性操作登记。
- [x] 成功回执只更新原项目中对应草稿的投影。较早的列表结果应用回执到该草稿，同时保留其他章的新数据。失败保留原行并反馈，切项目后不发布旧回执。保留其他流程使用的通用状态 IPC。
- [x] 用真实内存 SQLite 覆盖同章同版本的独立草稿、确认后已定稿、错误章号、错误项目、重复与失败。补 React 入口回归和 IPC 对账。

## 任务 4　本地验收

- [x] 运行 TypeScript、core 独立编译、ESLint 零警告、架构边界、全量 Vitest、标准 Vite 生产构建和公开产物审计。回填本计划及架构索引并独立提交。

## 独立复核与项目切换

- 命令面板可直接切换项目。此前旧标签仍留在编辑器，同 ID 的新草稿可能激活旧项目的未保存正文。统一入口会在切换或创建前确认处置未保存编辑和行内修稿，并在发送请求前移出旧标签。取消确认保留旧项目和标签。打开失败时恢复原标签并按新会话重载列表。
- 主进程创建项目时临时初始化新数据库，创建结束恢复原连接，再由现有打开流程切换。打开过程中失败也恢复原连接，避免原项目的列表和草稿请求落到目标库。
- 修复归档与并行刷新互相覆盖的问题。早于归档的回执只修正相同草稿 ID 的状态，其他章节的读结果继续发布。
