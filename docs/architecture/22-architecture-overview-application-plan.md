## 实施记录

### 状态与来源

新增纯 core 的 architecture-overview 用例及窄端口，返回四类字段和后处理各自的结果。四字段复用 B1 adapter 中的严格读取和单次 project-core 查询；合法空字段保持 pending，整行缺失为 missing，单字段格式错误只令该字段失败。共享读取也拒绝把原始值/数组当作有效 core 行。

后处理只严格读取最新 run 的 allCriticalPassed，不再经吞错的旧 helper 读取 steps。无记录为明确的 null，异常/格式错误为失败。同项目失败部分保留已有投影并显示错误横幅及重试；新项目/同路径重开建立新视图，旧结果不能借保留策略进入新项目。

每次 load 使用最新请求语义，读取后核对来源和序号，再继续下一项 IO。组件的 success/error/finally 同样只发布当前请求；StrictMode 预演不会销毁仍在使用的实例。角色数量继续订阅已有 character store。

### 命令与文档打开

生成、角色检查和提取复用 B1 应用命令，确认前后检查 id/path/session。启动前占用同步标记，失败释放；提取由自身运行终态或移除释放 busy，忽略无来源广播中的“成功/失败”含义。旧版无来源事件仅提示重读当前绑定来源，带 runId 的完成事件则检查来源登记。

打开复用 editor-open 的来源和发布边界。dirty 或 inlineSession 标签在读取前直接激活；DB 读取途中才产生的编辑会话在发布前再次检查。若本次解析的是受保护标签的内存投影，发布仅激活当前标签，即使它已保存变干净，也不写回旧内存快照；标签已关闭则取消，避免复活已关闭的稿件。

四卡布局、计数、字数和已有反馈保留。卡片使用原生导航按钮覆盖原命中区域，提取按钮作为独立的兄弟操作保持置顶和阻断冒泡；新增入口可键盘聚焦，没有把嵌套操作塞进一个 button。
