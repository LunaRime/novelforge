# 第二阶段：写入链路合流（2026-11-05）

第一阶段已提交：`a0642f9`（架构文档）、`d2e38a0`（核心与迁移验证）。用户要求继续第二部分。

## 设计与边界

本轮执行 M2 的应用链路合流，不自动迁移真实用户库。原 DB 仍是现有项目事实源；文件核心继续独立验证。真实项目副本验收、完整生命周期适配完成后才能切换存储。不能把数据库 draftId 伪装成已迁移的稳定章节 id。

1. 草稿正文提交抽到纯核心用例与端口；DB 适配器封装现有 CAS/快照，主进程两个更新通道走同一用例，保留原通道签名与确认行为。
2. UI、agent、意图路由统一使用应用工作流入口；具体工作流构建仍由适配器执行。保留启动即回执、参数校验、错误类型和检查点恢复语义，不让 UI 依赖工具协议或 LLM 调用。
3. 删除 `chapterDir` 的字符串解析。原 DB 项目用真实 draftId 查询修稿/审稿，用显式 chapterNumber 查新版本号；这两个概念分开，不能用章号冒充身份。
4. `write_file` 拒绝直接写草稿 URI；将模型导向现有写章工作流，三语提示与工具描述同步。通用文件工具也不能写未来章节正文目录。
