| 消费者 | 处理 |
| --- | --- |
| 角色卡、关系图、反向链接 | 保留角色 UID，事务内更新行与 `characters.relations` 的结构化目标 |

| 出场统计与正文扫描 | 改名前的名称加入别名，扫描仍能匹配旧正文。显式扫描对原角色身份和统计基线进行比较后提交。正文、档案文字、历史摘要及向量索引按原始文本保留 |
| 导出与历史记忆 | 新读取使用已提交的角色表和蓝图。已写出的导出、定稿正文、历史快照与自由文本记忆保留原文 |

## 实施与独立复核

- 角色编辑使用原名、UID、字段基线和提交值。改名用 SQL 更新原行的名称并保留创建时间。写入、结构化角色关系和蓝图出场引用在同一事务中提交。SQLite 触发器拒绝写入或写入零行时，事务回滚。
- 保存过程中发生的新改名和字段编辑以提交回执为基线重放。删除会清理提交中继续编辑的同一角色名称。首次读取完成前新增的角色会合入基线后保留为待保存状态。
- 架构提取和导入以模型调用前的角色身份绑定结果，写入时重新读当前卡片并填空。旧结果按 UID 找到改名后的同一张卡，已删除的身份不会被重新建立。档案补全继续复用 `mergeFields` 的哨兵规则。定稿动态状态仍走 `updateState`，定稿关系、声音与显式出场统计改用带基线的更新。
- 导入步骤确认、档案提取和架构后处理检查项目会话。同路径重新打开后，旧模型结果及旧步骤状态不进入新的连接。
- 角色加载改为只读。旧的括号名自动修复曾在加载时另发写入，也可能把手工角色名当作重复项合并。现有括号名通过别名匹配读取，历史修复计划保留供专项迁移核对。
