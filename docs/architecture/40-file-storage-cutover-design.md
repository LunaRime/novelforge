# F1 文件存储切换设计与身份映射

E3 已验证导出内容，E4 已验证 Windows 打包旧版的隔离屏障与完整快照恢复。F1 先交付从已验证迁移清单生成的身份映射。本批在离线导出上运行，应用继续由现有 SQLite 入口服务。[副本验证](38-storage-export-verification.md) · [旧版隔离](39-legacy-storage-isolation-and-restore.md)

## 身份映射

源端的 `draftId` 只在对应项目内有意义。章号用于排序和定位蓝图。文件章节身份沿用已验证导出中的 `ch_…`，后续切换当前稿、改标题和重排时保持不变。项目 ID 与迁移清单 SHA-256 绑定这份映射的来源。

| 对象 | 映射规则 | 打开入口 |
|---|---|---|
| 当前主线稿 | 采用当前章节文件中的 `chapterId`。同章其他版本及分支引用该章节身份。 | 文件项目内解析 `doc://chapter/{chapterId}`，仓储按 ID 查找当前文件。旧草稿定位符解析时还需匹配该条目的 `draftId`。 |
| 有当前主线稿的历史稿 | 每条 `draftId` 保留其版本、分支和独立的导出历史路径。 | 按精确历史稿打开，保持只读。 |
| 仅有历史稿的章节 | 以章内最小 `draftId` 对应的已导出 ID 为稳定章节身份。迁移格式 v1 仍以各历史稿原有的文件 ID 和路径存放正文。 | 历史入口携带导出文件 ID 与路径。该章节在显式恢复前没有当前稿。 |

运行 `node scripts/verify-storage-export.mjs <offline-db-copy> <pristine-export-directory> --identity-map` 可输出独立 JSON。映射包含格式版本、项目 ID、源指纹、迁移清单哈希，以及每条旧草稿的章节 ID、版本、分支和打开目标。输出重定向至导出目录之外，便于保留原样导出的文件清单。

映射记录迁移时的打开目标，历史条目还绑定导出文件的 SHA-256。无界面联调用文件仓储与现有文档打开用例读取当前稿和历史稿。旧当前稿定位符发现当前文件已经换稿时返回不可用。接入持久化版本目录后，可按原草稿身份定位后续归档的版本。

## 启动、编辑与故障恢复

1. **准备**。获取原项目一致快照，保存完整归档，导出到独立目录并完成正文、历史、关系和身份验证。预备目录只在工具中打开。F 接入需将已验证映射随候选项目持久化并记录校验值，准备阶段可重复执行。候选项目保存 E4 验证过的旧版 SQLite 路径屏障。
2. **激活**。由新版本的项目入口提交激活记录，记录项目 ID、已验证目标、映射校验值和会话代次。提交前复核隔离屏障和目标内容，关闭切换涉及的旧写入会话。提交后新会话统一走文件仓储和保留 DB 的业务入口。启动时激活记录或映射缺失、损坏或不一致的项目进入可诊断状态，直到恢复结果明确。旧项目入口和旧版最近项目记录继续表示快照时间点。
3. **文档身份**。现有 SQLite 文档使用数字 `docId` 和 `vela://draft/{draftId}`。文件文档使用项目范围内的章节 ID 和专用定位符。旧标签、Agent 上下文和 checkpoint 只在匹配项目与映射时重解析。当前稿与历史稿使用不同的打开目标。缺失映射显示不可恢复状态，保留原定位符供核查。项目路径、会话代次和存储后端均通过核对后才发布文档或接受保存。
4. **写入**。正文保存使用文件 revision CAS。文件成功发布后派生索引可独立重建。涉及修稿合并、归档、定稿等跨文件和 DB 的操作在 F2 落地可恢复提交协议，启动时通过操作身份核对是否已应用。保留 DB 的卷、蓝图、角色、世界、自动化和工作流入口继续按各自职责写入。[生命周期矩阵](37-storage-lifecycle-matrix.md)
5. **回退**。停止切换项目写入，先保全切换后新增的文件稿，再按 E4 的流程在新目录用匹配版本恢复完整归档。恢复完成后以归档时间点标识恢复入口。[恢复验证](39-legacy-storage-isolation-and-restore.md)

## 准入验收

- F1 映射验收涵盖当前与历史定位、同章多版本及分支、仅历史章节、不同项目的相同草稿 ID、清单篡改和重复导出。
- 用 E3 的 7 个真实项目副本各校验两份独立导出。20 条草稿映射一致，其中 16 条指向当前稿，4 条指向历史稿。另用文档打开用例逐条打开隔离副本中的 20 份正文，比对正文哈希及历史只读属性。映射和副本保存在仓库外。
- 无界面契约验证当前稿与历史稿分别打开、历史只读属性、改号后重新打开仓储、旧定位符拒绝错稿、历史文件篡改和项目会话变更。[文档打开契约](../../src/contracts/storage-export-verification.contract.test.ts)
- Electron 候选编辑器通过受保护的 `project:file-editor-open/save/close` 调用打开和保存。先通过应用目录选择授权候选副本，在副本内保留 E4 屏障，并将验证输出保存为 `.novelforge/draft-identity.json`。候选描述 `.novelforge/file-editor.json` 包含 `format: 1`、`projectId` 与映射文件的 `identityHash`（SHA-256）。打开时核验描述、映射、清单与屏障，接收上一会话的标签定位符，返回可打开标签及缺失定位符。保存使用当前稿的 revision 和当前窗口会话令牌。
- 主页「文件项目编辑器」使用该接口，并按目录保存已打开文档和选中项。重启后重新选择同一目录时恢复文档。编辑器保留保存失败后的修改，用户可以保存或显式放弃。
- IPC 回归覆盖控制器重建后重开已保存标签、历史写入拒绝、过期 revision 和跨窗口令牌拒绝。Windows 生产构建在隔离 Electron 进程中通过真实 preload 与 IPC 保存当前稿，正常退出并重启后恢复只读历史稿。自动化提供了系统目录选择结果。安装包和正式项目激活随 F2/F3 验收。
- 激活前跑完生命周期矩阵、故障注入、打包版隔离与恢复，验证每个写入口按激活状态选择同一个正文数据源。
