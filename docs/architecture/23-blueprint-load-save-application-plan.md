## 实施记录

### 交付边界

新增泛型 chapter-blueprints 核心用例与 renderer adapter。列表严格读取，默认章节升序复用 get-all 快速路径，其他排序沿用既有 sorted IPC。角色定位仍复用旧归一化函数，不改枚举或排序规则。列表和下一可写章号成功后共同发布，失败不生成伪空结果；写操作捕获独立快照，单项/批量保存实例内互斥。

ChapterCardEditor 按项目 id/path/session 建立视图，用当前行对象引用代表该行的编辑版本。编辑会替换行对象，单项保存只确认提交时对象；其他行、保存等待中新对象仍保持 dirty。全量保存同样按提交对象确认。角色数组和正文由 core 深拷贝后送往持久化端口；成功保存后的文件树失败作为独立 refreshError 反馈，不抹掉保存成功。

自动刷新遇到未保存行会跳过；手动重载使用已有三语丢弃确认，确认或读取期间的新编辑/保存令旧读取失效。首次失败显示错误/重试，不提示空库成功，也不允许以未知列表创建新章。原有新空行仍自动保存并保留待编辑提示；这是既有入口接线，不是新增创建或改号协议。

校检使用独立读取实例，避免其查询淘汰编辑器列表刷新；生成/删除等尚未迁出的入口只增加必要的来源检查。此次并未迁出这些业务，也没有改变目录生成、草稿身份、排序写入或卷归属协议。

### 事务与失败回归

仓储已有 upsertMany 事务，生产代码未改。使用 node:sqlite 的真实表和 SQL trigger，分别让第一行更新/插入成功、第二行失败，验证全表正文规划、角色数组、排序/优先级/卷元数据及时间戳全部回滚。测试显式 mock Electron 和数据库入口，未依赖本机 Electron 二进制。

组件首轮 7 条失败，覆盖保存中新输入、其他行脏状态、来源变化、刷新失败、重载取消和失败列表；后续补删除失败保留选择。独立复核发现新增的行对象版本与原删除等待期冲突：输入替换对象后，旧引用过滤可能留下已删行。补失败回归后，在删除等待期禁用编辑与冲突操作，并按确认的章号移除行，失败保留选择与 dirty；没有改变 delete IPC 或扩展删除事务。

默认排序显式传参的快速路径补了红绿回归。部分边界门禁先观察六条失败，再禁止组件中的加载/保存 IPC 与旧运行时 helper，保留未迁出的删除/生成入口及 type-only DTO 导入；没有声称整组件已无 IO。
