# 编辑器应用层抽离（2026-11-06）

基线：已合并的 `626bbda`，分支 `codex/editor-application`。用户已确认继续上一轮提出的编辑器改造批次。

## 目标与范围

沿用当前界面和 DB，将编辑器与侧栏中的数据读取、保存、修稿合并、审稿/定稿与翻译编排抽离到应用用例。组件负责显示、输入、确认与反馈，renderer adapter 负责接线，纯核心用例负责操作顺序和项目作用域。临时未保存正文与 inline 接受会话继续属于编辑会话，不能以刷新投影为由覆盖它们。

目前 DraftEditor 直接调用 IPC、模型 store 和工作流；SidebarShared 在异步读盘后直接开标签。这些路径分别存在业务与 UI 耦合、源项目过期后仍打开标签的风险。

## 实施清单

- [x] 定义窄端口和可独立测试的编辑器用例，core 不导入 React、Zustand、IPC 或组件。
- [x] DraftEditor 调用控制器/适配器，移除直接 DB、LLM 与工作流编排；保留原确认、三语提示、保存日志和手动/自动保存区别。
- [x] 侧栏通过打开文档用例读数据与发布标签；读取失败不伪装为空正文成功。
- [x] 所有异步操作在源项目/session 内执行；同路径关闭重开也失效，失败不清理 dirty，不覆盖等待期间的新输入。
- [x] 补用例测试与真实调用入口回归，覆盖保存失败、异步项目切换、只读/定稿、dirty 和 inline 状态。
- [x] 独立审查后通过全量 TypeScript、ESLint、Vitest、core 编译、边界检查、生产构建与公开产物审计。

## 实施约束

既有 CAS/事务/快照写入仍复用原实现，不复制一份保存语义。不迁移用户库、不冻结旧表、不改版本、URI 或真实文件路径。应用命令不发 toast、不决定面板外观；反馈文案由 UI/controller 使用既有三语字典生成。renderer 适配器允许读取 stores，但不能把整个 store 当成应用端口。

## 验收

使用内存/延迟端口可验证编辑器操作顺序与错误，不需要 React 或 Electron。组件不再直接发出数据库和模型调用；侧栏延迟读取期间切项目不会打开旧项目文档。既有正文保存、修稿合并、定稿只读与 inline 编辑行为通过回归验证。

core 对外通过唯一公共入口导出；UI 布局和可见交互沿用当前实现。本轮不是全部前端迁移，其他面板后续逐条接入同类用例。
