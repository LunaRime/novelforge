# F3 文件项目 Windows 验收与回退

2026-11-19 在 Windows x64 使用 `3720f5b` 的 `0.1.7-beta.3` 便携应用和已发布的 `0.1.7-beta.2` 便携应用验收。应用使用各自隔离的配置和项目副本，通过生产 preload 调用实际项目入口。测试数据为合成稿件。[旧版资产](https://github.com/LunaRime/novelforge/releases/tag/v0.1.7-beta.2)

## 版本与分支完整性

用 `beta.2` 创建 Schema v19 项目及两个主线版本。关闭应用后保留完整归档，将副本用 `beta.3` 升级至 Schema v23。通过 SQLite 项目的分支入口，以不同主线稿为基线创建两个分支。主线旧稿与两个分支稿同章同版本，三份正文各不相同。为 Schema v23 项目单独建立激活前归档，再运行迁移、导出验证与候选项目准备命令。[候选准备](41-file-commit-recovery.md#准备候选目录与冻结旧章表)

| 验收 | Windows 实测结果 |
| --- | --- |
| 身份与关联 | 迁移映射保留两条分支各自的 `draftId`、`branchId`、版本及历史文件摘要。保留库保有分支状态、基线快照和 head 稿件的关联，尝试修改冻结的分支 head 时被拒绝。 |
| 激活并重启 | 常规打开入口分流到文件项目编辑器。主线当前稿可编辑，同章主线旧稿及两个分支稿分别按旧草稿定位符或历史定位符打开，内容准确、保持只读。写入历史稿被拒绝。 |
| 当前正文与全文索引 | 保存激活后的当前稿并重建索引，检索分块对应新正文。上一批另行验证删除索引后重启重建及全文命中、合并中断后的启动恢复、定稿和归档后的只读状态。[全文索引重建](41-file-commit-recovery.md#全文索引重建) |
| 旧版隔离 | `beta.2` 拒绝打开激活目录，最近项目列表没有新增该目录。激活项目内各文件摘要前后一致。 |
| Schema v23 回退 | 核验归档摘要后恢复到独立目录。`beta.3` 打开及重启均读回归档时的主线和两条分支，并逐条核对分支基线和 head。 |
| Schema v19 回退 | 将升级前归档恢复到另一个目录。`beta.2` 打开及重启均读回归档时的两个主线版本。两份恢复库各自保持原 Schema，并通过 SQLite 完整性检查。 |
| 回退后重开文件项目 | 两份归档和源项目摘要保持一致。激活后的正文已单独保全。重新打开原文件项目时，激活代次、切换后正文和只读分支仍可读回。 |

两份归档均包含 SQLite 主库、作者笔记和独立资料文件。解包后、首次打开前逐文件核对 SHA-256。归档、自动化记录和项目副本保存在仓库外。

## 回退步骤

1. 停止对激活项目写入，把切换后需保留的文件稿另存到独立目录，并核对文件摘要。
2. 按目标时间点选用完整归档，核对项目、匹配应用版本、Schema 和归档 SHA-256。升级前归档用于回到升级前状态，激活前归档用于回到激活前的 SQLite 状态。
3. 将归档解包到新目录。核验完整文件清单与摘要，再用匹配版本打开。按稿件 ID 核对正文、基线、分支 head 等关联并重启复验。
4. 将恢复目录标记为对应归档时间点。保留激活项目和另存的正文，回退入口始终指向恢复目录。

## 交接范围

普通 SQLite 项目继续由现有工作台和 SQLite 草稿服务提供版本及分支创作。激活的文件项目通过专用编辑器写 Markdown 当前稿，旧版本和分支正文按映射只读打开。分支基线和 head 关系保留在冻结的旧章表，日常创建、合并分支仍由普通 SQLite 项目入口提供。派生全文索引可重建，保留库继续承担已接入的修稿及其他业务数据。[生命周期矩阵](37-storage-lifecycle-matrix.md) · [前端交接](42-v3-frontend-delivery-plan.md#0-后端交接与前端职责)

本轮证据来自 Windows 打包应用与合成项目副本。远端 CI、其他平台及 V3 正式工作台接入按各自计划验收。旧表清理仍按原计划独立审批及验收。
