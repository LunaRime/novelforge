# V3 U7 集成、性能与真机验收

**目标**。用固定的大项目样本发现布局、正文和会话更新的回归，并在正式桌面包中验证完整的创作、保存与恢复路径。

**实施条件**。Storybook 提供可重复的集成预验收。正式签收需要固定 U1–U6 的接入提交、第 42 号计划第 0 节的项目交接范围及实际待发包版本。普通 SQLite 项目与文件项目分别登记可执行操作和回退证据。[V3 总计划](42-v3-frontend-delivery-plan.md#0-后端交接与前端职责)、[U0 输入延迟基线](43-v3-u0-baseline.md#输入延迟基线)

## 1. 固定可回归样本

- 在 **NovelForge Workbench → V3 Performance → Large Project** 打开合成项目。左侧 1,000 章，第一章正文 100,000 个 UTF-16 码元，右侧 500 条消息。搭档区的运行测试和停止按钮控制末条消息按 150 ms 更新，其他消息和章节仍可滚动查看。[样板源码](../../src/stories/V3Performance.stories.tsx)
- 使用 1440×900 和 684×428 CSS 视口各跑三轮。每轮分别在消息空闲和更新中插入 8 个单字。逐字等待 `beforeinput` 后的 `requestAnimationFrame` 和文档回读，再发下一字。记录中位数、P95、最大值和空闲帧间隔。
- 度量前核对初始文档长度、行数及消息数。观察正文与长列表的 DOM 更新。把会话停在旧消息处，检查滚动位置保持。末条消息更新期间关闭再打开搭档，验证编辑器实例和输入继续保留。响应性结果以实际测量环境登记。

在两个视口均已核对 1,000 个章节入口、100,000 字符长稿和 500 条消息。模拟流更新命中末条消息，观察到的历史消息及章节列表文本和节点更新次数均为 0。查看旧消息时滚动位置保持，隐藏搭档期间仍收到更新。恢复搭档后编辑器实例相同，打开第 1,000 章再切回第一章时保留了 48 字符的编辑。

### 帧调度诊断

Windows 11 上用项目的 Electron 43.8.4，在独立配置的隐藏测试窗加载 Storybook 构建产物，窗口设置 `backgroundThrottling: false`。每个视口和条件记录 24 次单字插入，均等到独立帧回调并回读正文。以下是合成输入时的诊断数据，前台打包版记录见第 3 节。

| CSS 视口 | 模拟输出 | 中位数 | P95 | 最大值 |
| --- | --- | ---: | ---: | ---: |
| 1440×900 | 空闲 | 996.7 ms | 1002.7 ms | 1003.3 ms |
| 1440×900 | 更新中 | 997.7 ms | 1005.8 ms | 1014.4 ms |
| 684×428 | 空闲 | 997.2 ms | 1003.4 ms | 1004.3 ms |
| 684×428 | 更新中 | 997.9 ms | 1003.6 ms | 1004.6 ms |

同一采集方式下，独立页面的原生 `textarea` 有 7 次输入同样等待约一秒后才收到下一帧，8 次输入的微任务耗时均在 0.1 ms 内。可以用原生对照复现这段帧等待。正式计时使用前台实际窗口，先对照空闲帧和原生输入，再与 U0 对比。原始记录保存在本地 `.test-artifacts/v3-u7-performance/benchmark-results.json`、`native-input-control.json` 和 `throttled-results.json`。

### 前台打包版性能

Windows 125% 系统缩放。两个视口各跑三轮，使用 1,000 章、100,000 UTF-16 码元正文和 500 条消息。每轮分别采集空闲与回环模型每 150 ms 发送一段时的 8 次输入。共核对 96 次输入和 6 次完整 SQLite 回读。空闲帧间隔为 5.5–5.6 ms。

| CSS 视口 | 空闲中位数 / P95 | 流式中位数 / P95 | 原生 textarea 中位数 / P95 |
| --- | ---: | ---: | ---: |
| 1440×900 | 7.30 / 10.90 ms | 7.55 / 8.80 ms | 1.85 / 3.50 ms |
| 684×428 | 7.65 / 10.70 ms | 7.50 / 9.30 ms | 1.85 / 4.30 ms |

六轮流式输入中，历史消息和章节导航的文本及节点变化均为 0。500 条历史消息与阅读位置保持，正文实例在两态往返和搭档召回时保持连续。宽、窄视口的卷展开用时分别为 626 和 577 ms，打开第 1,000 章分别为 891 和 701 ms。原始数据目录为 `performance-jpSgGl`。U0 参考中位数为空闲 4.7 ms、流式 4.4 ms。

同一夹具、脚本、设备和输入节奏复测历史包 `49392a2`（`performance-d8AY07`）。该包宽窗空闲与流式的中位数／P95 分别为 7.00／10.40 ms 和 7.50／10.00 ms，窄窗为 6.60／11.80 ms 和 7.25／8.30 ms。最终包宽窗中位数增加 0.30／0.05 ms，窄窗增加 1.05／0.25 ms，P95 在两次运行中有升有降。U0 与最终包直接比较所见的约 3 ms 宽窗差距，在同夹具复测中未重现。
