# C1d 蓝图生成入口、补缺口与校检计划

基线 `22ac0d2`。承接 18 与 26。C1d 接入目录生成前检查、补缺口启动与校检查询。生成任务内部的写入协议、整本流水线和 DraftBoxGroup 各自保持独立验收。

- [x] 校检纯计算接收一次严格蓝图快照，缺口按连续区间，前章取区间起点之前、后章取终点之后。覆盖读取失败、连续缺口、部分生成的角色阈值和兼容上下文。保留现有报告契约、角色归一化、严重程度及 prompt 上下文语言。编辑器/后台校检/命令都使用同一严格读取和报告逻辑，失败不返回伪空成功。
- [x] 编辑器校检不再查询无关的定稿最大章号。复用会话来源检查、最新请求与失败保留。校检期间的编辑器删除/保存应淘汰旧报告，确认中的目录请求捕获参数值。
- [x] 目录生成前检查移入已有工作流启动适配器。编辑器通过可选的 warning 确认回调接入，拒绝或过期不启动。其他调用者默认延续原本允许警告的行为。确认前后检查来源，防重复提交，guard 读取异常进入可见反馈。
- [x] 补缺口启动前按当前严格列表重核目标。若整组目标已填或部分已填，拒绝当前报告的补写并引导重校检，避免对旧缺口发起覆盖。该检查只约束派发前，执行中的并发写入与生成结果事务另列专项。
- [x] 先补失败回归，再实现、独立复核和全量门禁。更新路线、索引与验收记录并独立本地提交。工作流批量清理目前仍逐条 IPC，主进程原子替换与补写仅填空需另批设计。

## 2026-11-11 实施记录

本批只延续后端 C1d，不包含独立 UI 原型，也未进入生成内部写入协议或草稿列表改造。

- 新增 `src/core/application/blueprint-verification.ts`，按一次快照生成连续缺口、相邻边界、角色定位及严重程度。renderer 报告层保留既有字段、三语摘要和中文补写 prompt 上下文。
- `readChapterBlueprintSnapshot` 复用严格列表读取及项目 id/path/session 检查；编辑器、后台扫描和 `VerifyBlueprintsCommand` 共用，不再查询缺口和相邻单章。后台扫描支持从已加载的 checkpoint 快照计算报告。
- 编辑器校检失败保留前次报告，保存/删除使旧校检请求失效；目录启动以共享入口捕获参数，warning 拒绝不派发，启动回执之前不显示“已提交”，并用本地锁阻止双击启动。
- 补缺口派发前重读列表，任一目标已存在即拒绝并提示重新校检；core 拒绝不连续或重叠的目标。
- 独立复核修正合法数字 `notesUpdatedAt` 被拒：DTO 同时接受毫秒戳与旧字符串，数字校验为非负安全整数，SQLite 测试夹具改用生产 INTEGER 列并验证 `updateNotes`。
- 修正同项目切标签、编辑器卸载后的派发：可选 `isCallerCurrent` 独立于 warning 回调检查，最终 start 前再次核对；未提供回调的其他调用者保留既有行为。
- 仓储 `getAll/getAllSorted` 在 DB 不可用时抛错，避免合法空列表与读取失败混淆；未改变 schema、事务或 IPC 签名。
