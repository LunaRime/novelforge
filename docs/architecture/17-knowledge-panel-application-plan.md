# 知识库侧栏应用层抽离（2026-11-06）

基线 `4e251e1`，分支 `codex/knowledge-application`。用户确认按上一轮提出的顺序，继续知识库前端职责拆分。

## 范围与职责

本批处理 `KnowledgePanel` 的列表/统计加载、搜索、摘要、文档标题读取与删除；不修改知识库总览的向量/分词回填，也不改变检索算法、schema、版本、存储格式或 UI 布局。

纯核心应用用例通过窄端口读写，renderer adapter 连接现有 IPC、文档读取和模型。组件/控制器负责输入、可见状态、确认、日志与三语反馈。controller 可以管理 loading 与请求展示状态，但不能把原组件里的 IPC/LLM 调用原样搬进 hook。

## 实施清单

- [x] 中立数据类型与核心知识库用例，经 core 公共入口导出，无 React/Zustand/Electron 依赖。
- [x] renderer 适配器复用既有检索与严格文档读取；读取失败与合法空正文分开，保留摘要截取 30,000 字符和本地化系统提示。
- [x] 面板通过应用 API 加载、搜索、摘要、读取标题和删除，移除直接 IPC/LLM store 调用。
- [x] 按值捕获项目 id/path/session；确认期间切换项目或同路径重开不得把旧操作派给新会话。
- [x] 搜索按最新请求发布，输入变化/清空取消旧请求；晚到成功、失败和 finally 不能覆盖新结果或 loading。
- [x] 摘要关闭、组件卸载、项目切换后取消发布；标题读取失败仅回退展示名，不伪装为整个列表加载失败。
- [x] 删除失败保留文档；删除成功后刷新失败仍报告删除成功，区分投影刷新错误；失效旧搜索/摘要/加载，避免删除后结果复现。
- [x] 实际组件/控制器回归与独立复核后通过全量 TypeScript、ESLint、Vitest、core 编译、边界门禁、生产构建和公开产物审计。

## 验收

延迟端口可验证 A/B 搜索乱序、清空搜索、摘要关闭、同路径项目重开、删除失败和成功后刷新失败。UI 继续沿用 React/TypeScript、Zustand 展示状态与现有组件；不乐观隐藏删除失败的文档，不用空结果掩盖失败。临时日志统一写 `logs/tmp/`。

本批不宣称整个知识库模块或全部前端已完成迁移；总览页和其他面板后续逐步接入同类用例。

## 必要的主进程补修

原 `kb:remove-document` 将异步 `removeDocument` 的 Promise 放入 `success` 字段，既不符合 IPC 布尔返回契约，也无法反映删除失败。本批补上 await，并以主进程 handler 回归验证 true、false 和异常；未改变检索算法或删除范围。
