| 面 | 应有行为 | 依据 |

| 行 | 高 32px 行片；名称 +（自定义标签）+ 灯 + [编辑][删除]；**点整行 = 点编辑**（无死带） | spec §1/§2.1 |
| 单开 | 点第二行的编辑 → 第一张卡收起；**有脏草稿时先弹确认**，取消则原卡不动 | spec §2.2 |
| 只写密钥 | 密钥框**初值恒空**；已存密钥读不回；空 = 不变更；框里只有 placeholder 三态 | spec §4.4 |
| 三态灯 | 绿=已配置 / 红=ref 已分配但 env 与库皆无 / **无灯**=describe 未完成或失败（不阻塞行） | spec §4.5 |
| placeholder 三态 | env 影子 → 「由环境变量 X 提供（只读）」且框**禁用**；已配置 → 「已配置（留空保持不变）」；否则 → 「输入 API 密钥」；ollama → 「留空 = 不使用密钥」 | §4.5 / `credential-field.ts` |
| 应用顺序 | 先落账户配置（带 revision 校验）→ 成功后才写凭据；凭据失败 → 「配置已保存，密钥未写入」+ **保留草稿** | spec §4.7 |
| 删除顺序 | 引用检查 → 确认 → **先凭据 unset、后配置删除**；unset 失败 → 中止且账户**仍在**；env 影子 → 跳过凭据步骤 | spec §4.7 |
| 目录三态 | `undefined`=继承（meta「默认模型目录」）；有值=自定义（meta「已自定义模型目录」+「恢复默认模型」按钮出现） | spec §5 |
| 获取可用模型 | 内置目录命中的家 → **免网络直答**（不出网）；ollama → 原生 `/api/tags`；其余 → 端点探测 | spec §5 |

>
> **为什么这样就能失败**：`writeJsonFile()` 是 **tmp + rename** 的原子写（`config-utils.ts:178-195`）——
> 临时文件建在**同一个目录**里（目录可写 → `writeFileSync(tmp)` 成功），最后一步 `renameSync(tmp,target)`
> 覆盖一个带只读属性的文件，在 Windows 上返回 **EPERM**（2026-10-01 本机实测：`writeFileSync(tmp): OK` /
> `renameSync: FAIL EPERM`；`attrib -R` 后同一操作 OK）。失败点正好落在**凭据那一步**，
> 于是「配置已落盘、密钥没写进去」这个待测状态自然出现。
>
> ⚠️ **不要用 `icacls` 把整个目录 deny 掉**（初版文档的错误建议）：那会让**同目录的 `providers.json`
> 也写不进去**，保存链路在第一步 `mutateProviders` 就失败、`save-provider` 提前返回**不带 revision**
> 的失败 → toast 是笼统的「保存失败」、C6 的 `revision +1` 也不会发生 —— C5/C6 会双双变成**假缺陷**。
>
> 副作用：施加期间**只有凭据写入**会失败（其它配置照常）。若执行人不愿改文件属性，C5/H4 可标
> **阻塞** —— 核心判据（写失败不关卡、账户不删、文案区分）在静态测试里已有覆盖，标阻塞不算失败。

> ⚠️ **做法说明（执行人必读）**：**本应用是单窗口的** —— `electron/main.ts` 只有 `createWindow()` 一处
